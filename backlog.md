## Оптимізація архітектури (з рев'ю)
- [ ] **Дублювання десеріалізації категорій**: 
  `layout.tsx` викликає `getPublicCategories()`, а `page.tsx` -> `getHomepageData()` знову викликає `_getPublicCategoriesRaw()`. Дані беруться з кешу, але це зайва робота для сервера.
  *Рішення:* Передавати частину даних через пропси або використовувати React `cache()` для мемоїзації в рамках одного реквесту.
- [ ] **Drizzle Relational Queries (`db.query.*`)**: 
  У `category-service.ts` використовується `findMany` з `with: { children: true }`. 
  *Рішення на майбутнє:* Поки категорій небагато — це окей. Якщо дерево стане глибоким (3-4 рівні), варто переписати на один `SELECT` з `LEFT JOIN` або рекурсивний CTE-запит для кращої продуктивності бази даних.

## Вирішені питання та Нотатки
- **Робота з `numeric` полями в Drizzle**: Drizzle віддає їх як `string`. 
  *Статус: Вирішено.* У `zustand` сторі (`use-cart.ts`) вже коректно використовується `parseFloat(item.price)`.
- **It is ok that we put api folder into app folder?**: 
  *Відповідь: Так, абсолютно.* У Next.js App Router бекенд API роути повинні знаходитись саме у папці `app` (наприклад, `app/api/.../route.ts`). Це стандартна практика.
