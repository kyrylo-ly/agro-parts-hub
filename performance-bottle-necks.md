# Аналіз та оптимізація продуктивності (Performance Bottlenecks)

Цей документ слугує планом для пошуку та усунення "пляшкових горлечок" у продуктивності проєкту, враховуючи жорсткі пріоритети (Безкоштовність -> Серверна оптимізація -> SEO -> Мінімальний JS -> Клієнтська оптимізація).

## 1. Як шукати "пляшкові горлечка" за допомогою інструментів

### Vercel Speed Insights & Web Analytics
- **Що показує:** Реальний досвід користувачів (Core Web Vitals - LCP, INP, CLS).
- **Як використовувати:** Знайти сторінки з найгіршим показником TTFB (Time to First Byte) та LCP. Це вкаже, де сервер занадто довго генерує сторінку.

### Chrome DevTools
- **Network Tab (Мережа):** 
  - Дивимось на `waterfall` завантаження. Якщо перший документ вантажиться довго — проблема на сервері/БД.
  - Фільтруємо по `JS`, щоб побачити розмір бандлів.
- **Performance Tab (Продуктивність):**
  - Записуємо профіль завантаження сторінки. Дозволяє знайти "довгі задачі" (Long Tasks), які блокують головний потік (Main Thread) через надлишковий JS або складний рендер.
- **Lighthouse:**
  - Синтетичні тести. Корисно для загальної оцінки SEO, Accessibility та Performance в ідеальних умовах.

### Neon DB & Drizzle
- **Neon Console:** Моніторинг використання CPU/RAM бази даних та час виконання запитів.
- **`EXPLAIN ANALYZE`:** Використовувати для повільних запитів, щоб перевірити, чи використовуються індекси (особливо GIN для JSONB).

### Next.js Bundle Analyzer
- **Що робить:** Генерує візуальну карту розміру всіх JS пакетів.
- **Як використовувати:** Запустити `ANALYZE=true pnpm build`, щоб знайти важкі бібліотеки, які можна замінити на легші альтернативи або завантажувати ліниво (Dynamic Imports).

## 2. Комунікація з AI: Хто що робить?

### 📤 Яку інформацію вам ТРЕБА надати мені (AI):

1. **Регіони інфраструктури (КРИТИЧНО для TTFB):**
   - У якому регіоні розгорнуто Vercel (наприклад, `fra1` - Франкфурт, `iad1` - Вашингтон)?
   - У якому регіоні знаходиться база даних Neon?
   - *(Якщо БД в США, а Vercel в Європі — це гарантоване відставання в 100-200мс на кожен запит до БД).*
2. **Дані з Vercel/Lighthouse:** Скріншоти, PDF-звіти або просто текст з проблемними метриками (яка сторінка найповільніша і який показник світиться червоним).
3. **Дані з вкладки Network (DevTools):** Якщо сторінка вантажиться довго, який час очікування (Waiting for server response / TTFB) першого документа?
4. **URL проблемних сторінок:** Наприклад, "гальмує сторінка каталогу з фільтрами" або "довго відкривається картка товару".

### 📥 Що я (AI) можу перевірити САМ у коді:

1. **Серверна оптимізація (Next.js & Drizzle):**
   - Перевірю файли сторінок (`page.tsx`) на предмет правильного використання Server Components vs Client Components.
   - Проаналізую запити Drizzle на наявність проблеми "N+1" (коли в циклі робляться додаткові запити до БД).
   - Знайду місця, де можна застосувати `React.cache`, `unstable_cache` або змінити стратегію рендеру на SSG/ISR замість чистого SSR.
2. **Мінімальний JS бандл:**
   - Перевірю `package.json` та імпорти в компонентах. Знайду важкі бібліотеки та запропоную легкі аналоги або налаштую `next/dynamic` для їх відкладеного завантаження.
3. **Оптимізація зображень (Cloudflare R2):**
   - Перевірю, чи правильно використовується компонент `<Image />` від Next.js і чи налаштовані `remotePatterns` для Cloudflare R2 без зайвого навантаження на Vercel Image Optimization (оскільки він має ліміти у безкоштовному тарифі).
4. **SEO та Метадані:**
   - Перевірю наявність генерації `generateMetadata` та JSON-LD (Schema.org) у відповідних компонентах.
